## Publication checks and remaining steps

### Hardening browser correction (2026-11-05)

The reported CI failure in `users.spec.ts` ran the owned hardening fixture with
`AUTH_MODE=developer`. That mode treats every request as Admin, including an
invited Ops user's requests, so the expected hidden User menu could not be
asserted. Browser-enabled hardening now overrides the owned fixture to session
authentication before startup. Non-browser fixtures retain developer mode.
The subsequent Kafka secret-boundary API inspection also authenticates its
client. The browser test asserts session mode and actual Ops/Viewer roles before
checking navigation, forbidden API actions and session revocation.

Verification of this correction: **92 regression tests passed**; the real
`users.spec.ts` Chromium scenario passed against a session-authenticated host API,
production web build and isolated PostgreSQL metadata. Its only pipeline was a
stopped metadata fixture for the forbidden-action assertion; no CDC was deployed.
Ruff, Prettier, ESLint and TypeScript checks passed. Logs are under
`artifacts/release-v0.3.4/user-rbac-fix/`, including
`focused-browser/summary.json` and `regression.xml`.

The complete local browser/hardening rerun remains **NOT RUN** because the prior
local API/web/Connect/MinIO fixture images were absent. A full-fixture startup
attempt recorded BLOCKED, separately from the passing focused browser scenario.
The correction is uncommitted locally and requires candidate CI on the new commit;
the previous green local preparation evidence does not certify that CI run.
