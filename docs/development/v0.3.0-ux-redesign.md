# ClueCDC v0.3.0 UX/UI redesign

## Scope and product boundary

This redesign treats ClueCDC as an operational control plane around Debezium,
Kafka, and Kafka Connect. It does not imply that ClueCDC transports CDC records,
verify destination freshness from connector state, or expose metrics not supplied
by the existing APIs. Existing routes, API contracts, deployment ordering, and
Viewer/Ops/Admin permissions remain authoritative.

The repository uses Next.js 16 App Router, React 19, TypeScript, React Query,
TanStack Table, Radix Dialog, Lucide, Tailwind 4, and global component classes.
Shared primitives live in `packages/ui`; domain components live in
`apps/web/src/components` and `apps/web/src/features`. Manrope and JetBrains Mono
are already self-hosted through `next/font/local`, so the redesign retains those
fonts instead of adding a network or package dependency.

The supplied multicolor ClueCDC artwork is the authoritative brand source. The
transparent logo is used in product and documentation surfaces, while the square
icon is used for favicon and social metadata.

## Simplification decisions

- Primary navigation no longer duplicates Topics, Consumer Groups, Error Center,
  Users, and Security. These supported routes remain reachable through their
  contextual parent pages and existing direct URLs.
- Kafka and Connect inventory remains Admin-only in primary navigation, matching
  the existing product contract. Ops keeps the read access required by pipeline
  workflows without gaining an infrastructure workspace.
- The header contains environment health, authorized alert state, theme, and user
  controls only. No global search or decorative notification source is invented.
- Historical throughput and lag remain explicitly unavailable when no metrics
  provider exists.

## Design system proposal

### Palette

| Role                | Light     | Dark      |
| ------------------- | --------- | --------- |
| Page                | `#F7F9FC` | `#0B1220` |
| Surface             | `#FFFFFF` | `#111C2E` |
| Secondary/elevated  | `#F1F5F9` | `#17243A` |

| Secondary text      | `#475569` | `#B0BED1` |
| Border              | `#E2E8F0` | `#29384F` |
| Primary interaction | `#2563EB` | `#60A5FA` |
| Sidebar             | `#0B1220` | `#070D18` |

Brand primitives are purple `#8B5CF6`, blue `#2563EB`, cyan `#22D3EE`, teal
`#14B8A6`, green `#22C55E`, yellow `#FACC15`, orange `#F97316`, and red
`#EF4444`. Green/amber/red/gray/blue operational tokens are separate from these
brand primitives.

### Typography, spacing, and shape

- Manrope: page titles, navigation, controls, and body copy; 14px default body.
- JetBrains Mono: IDs, topics, offsets, configuration, and metrics.
- Page title 26px; section title 17px; table/body 13–14px; labels/supporting copy
  12–13px.
- 4px base spacing with 8/12/16/20/24/32px steps.
- 24px desktop page padding, 16–18px surface padding, 46px table rows, and
  8/10/12px radii.

### Component variants

- Buttons: primary, secondary/outline, ghost, destructive.
- Status: success, warning, error, info/in-progress, paused/neutral, unknown.
- Surfaces: panel, metric summary, table, empty, error, loading skeleton.
- Navigation: active, hover, disclosure, desktop collapsed, mobile drawer.
- Forms: labelled field, hint, inline error, disabled, advanced disclosure.
- Data visualization: accessible pipeline rail with real runtime metadata only.

## Risks and mitigations

- Global CSS has accumulated legacy selectors. The semantic token layer and final
  v0.3 stylesheet minimize behavioral churn; future work should migrate feature
  blocks to CSS Modules without mixing that refactor into this release.
- Route removal would break bookmarks, so redundant items are removed only from
  primary navigation; routes remain intact.
- Wizard presentation changes can accidentally change deployment order. Unit tests
  continue to assert preview → save → capture deploy → topic preparation → delivery
  preview → delivery deploy.
- Visual sign-off includes the supplied logo at desktop, collapsed-sidebar,
  authentication, documentation, and mobile sizes.

## Testing strategy

- Vitest: role-aware navigation, theme persistence, sidebar/disclosure behavior,
  form validation, wizard state and review payload, lifecycle actions, dialogs,
  empty/loading/error states.
- TypeScript and ESLint on every implementation phase.
- Next.js production build after the final stylesheet and route changes.
- Playwright visual evidence for representative routes at 1440×1000 and 375×812,
  plus dark theme and mobile drawer checks.
- Manual keyboard review: skip link, navigation disclosure, tabs, sortable rows,
  dialogs, wizard controls, and Escape behavior.

Automated checks support, but do not by themselves establish, WCAG 2.2 AA
conformance.

### Accessibility findings

- Core text and action pairs meet WCAG AA contrast in calculated checks: light
  primary 16.93:1, secondary 7.58:1, primary action 5.17:1; sidebar text
  12.61:1 and muted text 7.30:1; dark primary 17.09:1, secondary 9.05:1,
  primary action 6.72:1. Light success/warning/error text is at least 4.83:1.
- Navigation disclosure and sidebar collapse expose names, expanded state, and
  persistent current-page semantics. Status remains text plus dot/color.
- Radix Dialog retains focus management; tabs retain arrow/Home/End behavior;
  data rows remain keyboard-openable; reduced-motion preferences disable
  transitions.
- Manual screen-reader and 200% zoom review is still required before claiming
  WCAG 2.2 AA conformance.

### Responsive validation

The visual runner exercised Overview, Pipelines, Pipeline Wizard, Deliveries,
Sources, Destinations, Monitoring, Alerts, Audit, and Settings at 1440×1000 and
375×812. It also captured dark theme and the mobile drawer. All routes rendered
without page-level horizontal overflow or browser page errors. Wide tables keep
their overflow inside the table region.

### Test results

- Frontend: 18 files, 49 tests passed.
- Targeted API release/RBAC: 60 tests passed.
- TypeScript, ESLint, Prettier, and Next.js production build passed.
- Visual runner: 10 routes, desktop/mobile, light/dark, passed.
- Release plan resolves `v0.3.0` and the three `0.3.0` container images without
  publishing anything.

The full release-quality command was not run because the required disposable
`WORKER_TEST_DATABASE_URL` was not provided. CI and target-environment review
remain required.

### Remaining limitations

- Brand assets are centralized under `apps/web/public/brand` and mirrored into
  `docs/assets` for static documentation builds.
- Legacy global feature CSS remains large. The v0.3 semantic layer is
  authoritative, but a future incremental CSS Modules migration would reduce
  selector debt.
- No live CDC, disposable PostgreSQL, Kubernetes, or cross-browser release gate
  was run as part of this frontend-focused workspace change.
