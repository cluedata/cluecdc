# v0.3.4 Data Quality implementation

This is an additive, unreleased implementation on `feat/cdc-validation`, based on
`f904ac3`. Existing uncommitted v0.3.3 reliability work is preserved. The initial
working-tree file hashes are recorded locally in `.codex-tmp/dq-original-state.json`.

Implementation order:

1. Baseline existing suites; add metadata, strict configuration, capability guards,
   read-only measurements, CRUD, RBAC and audit events.
2. Implement exactly six rules, canonical types and timestamps, shared measurements.
3. Reuse the existing Job worker/leases for durable scheduling and immutable runs.
4. Integrate the existing AlertManager, incidents, channels and delivery queue.
5. Add navigation, dataset discovery, five-step editor, check and run history.
6. Exercise isolated PostgreSQL/MySQL, scheduler, alerts, session browser flows,
   migrations and regression gates; publish actual evidence in the test report.

Eligible CURRENT_STATE pairs are PostgreSQL → PostgreSQL, MySQL → MySQL and the
subsequently authorized/verified PostgreSQL → MySQL direction. The reverse direction
remains blocked. Cross-provider measurements normalize timestamps explicitly;
Schema Match conservatively distinguishes known narrowing from unverified type
mappings. Operators attest current-state semantics. Comparisons are BEST_EFFORT
and never certify CDC completeness.
