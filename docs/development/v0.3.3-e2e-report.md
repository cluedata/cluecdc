# v0.3.3 CDC reliability validation

This milestone extends the existing Python acceptance utilities and
`source_e2e.py`. It adds no providers, warehouse stateful modes, migrations or
production deployment changes. Results are scoped to actual executed assertions;
historical v0.3.2/source-extension reports are not current evidence.

## Reproduce

Build the existing pinned runtime images, then execute the owned fixture runner:

```sh
docker build -f infrastructure/docker/api.Dockerfile -t cluecdc-reliability-api:local .
docker build -f infrastructure/docker/connect.Dockerfile -t cluecdc-reliability-connect:local .
docker build -f infrastructure/docker/minio-test.Dockerfile -t cluecdc-reliability-minio:local .
python scripts/cdc_reliability.py --execute --chaos --extra-sources
python scripts/cdc_reliability.py --execute --pairs postgresql:POSTGRESQL --snapshot-interruption --source-history-expiration
```

The default command without `--execute` generates a NOT RUN matrix and starts no
services. Select pairs with `--pairs postgresql:CLICKHOUSE,mysql:CLICKHOUSE`.
Use `--pairs none --extra-sources` for the optional-source suite alone. Each run
copies the existing Compose fixture configuration into an independently named
project, uses available loopback ports that remain stable across restarts, and
checks both project and run-ownership labels before stopping any container.
It never reads the local `.env`; public example fixture settings are isolated
from an existing deployment. Host images are operator-selectable and immutable
image IDs plus Connect plugin versions are recorded in the evidence.

Artifacts default to a unique run directory under `artifacts/cdc-reliability/`;
`--output PATH` selects an explicit directory. Outputs include summary, compatibility,
correctness, recovery, checkpoint and regression JSON, plus sanitized failure
diagnostics. A nonzero exit means a failed assertion or unavailable infrastructure;
missing cloud resources do not fail an unrelated local run. Every scenario has
bounded operations. Shutdown runs in `finally`, without deleting durable volumes.
`--retain-fixtures` explicitly keeps containers for debugging; the generated
Compose file lives in the OS temporary directory under the reported project name.
Stop retained services with `docker compose -p PROJECT -f COMPOSE_FILE down`.
Do not add shared volumes or external networks to these fixtures.

## Assertions and semantics

The PostgreSQL/MySQL runner signs in, creates source/destination connections,
tests connectivity/readiness, discovers the table, previews and deploys capture
and delivery, and exercises pause/resume/restart and audit through existing APIs.
It compares deterministic composite keys, a non-PK unique column, Vietnamese
text, decimal(30,9), nulls, booleans, dates, timestamps, binary and large text.
The non-PK unique column is fixture data, **not** live verification of selecting a
non-PK Effective Row Key. Existing effective-key regression tests remain required.

Snapshot success requires snapshot events plus persisted source offsets that
have left snapshot-in-progress. RUNNING alone does not satisfy the check.
INSERT/UPDATE/DELETE are checked in Kafka and at the destination. Current-state
delivery checks deletion and bounded final equality; append-only delivery checks
immutable history, never claims a materialized delete. Warehouse history compares
topic/partition/offset, key, operation, source and before/after JSON to real Kafka
events. Tombstones are inspected in Kafka; warehouse transforms may omit them.

Ordered fixture replay republishes the original wire envelopes to this run's
owned topic, preserving per-partition ordering and assigning new Kafka offsets.
It does not reset Connect or consumer offsets. JDBC final state must remain
equal; history retains deliberate logical repeats and reports coordinate
duplicates separately. Arbitrary out-of-order replay is not certified. Restart
success alone is not replay proof. No path gains an exactly-once claim.

MariaDB and MongoDB reuse the existing real adapter/config-builder/Connect runner.
MariaDB also checks PostgreSQL stateful CRUD; both check MinIO raw events,
including MongoDB BSON/patch preservation. Their full API/browser orchestration
journeys remain unverified. Their source outages explicitly use existing task
restart and are reported as operator-assisted recovery. SQL Server uses the real
API connection/readiness/preview/deployment/lifecycle path and Linux runtime
driver; its two final short outages recovered without a test-issued restart.

For browser coverage, first build the existing root `Dockerfile` as
`cluecdc-reliability-web:local`, install the existing web/Playwright dependencies,
then pass `--browser`. This reuses the existing demos and all 33 browser tests,
with real session authentication. `--sources mariadb mongodb` narrows the
optional-source suite without changing capability guards.

## Optional real cloud execution

No cloud dataset, bucket, Redshift cluster, Azure pool, storage account or Oracle
database is provisioned. Missing infrastructure is **NOT RUN — Real cloud
infrastructure unavailable**. Use dedicated pre-existing resources and a private
JSON file containing `authorize_test_writes: true` plus provider entries:

```json
{
  "authorize_test_writes": true,
  "BIGQUERY": {"config": {}, "credentials": {}},
  "REDSHIFT": {"config": {}, "credentials": {}},
  "AZURE_SYNAPSE": {"config": {}, "credentials": {}}
}
```

Populate each entry using the existing connection API schema and the destination
guides. Include only configured providers. Use dedicated datasets/schemas and
staging prefixes with least-privilege credentials, not shared production targets.
The normal API validates TLS and supported modes. Query verification uses the
existing authenticated SDK connection helpers inside the fixture API image;
credentials travel on stdin and are redacted from artifacts. SQL identifiers are
validated by connection/mapping APIs. Test tables are unique; staging prefixes
are suffixed by the run ID. Shared cloud infrastructure is never stopped.

```sh
python scripts/cdc_reliability.py --execute --cloud-config /private/cloud.json --pairs postgresql:BIGQUERY,mysql:BIGQUERY
python scripts/cdc_reliability.py --execute --cloud-config /private/cloud.json --pairs postgresql:REDSHIFT,mysql:REDSHIFT
python scripts/cdc_reliability.py --execute --cloud-config /private/cloud.json --pairs postgresql:AZURE_SYNAPSE,mysql:AZURE_SYNAPSE
```

Dedicated cloud datasets/schemas must already exist. Test tables, marker tables
and staged objects are retained for evidence; the operator applies the dedicated
test retention policy. Cloud execution may incur charges and requires the
explicit configuration flag. Service-principal/password credentials must be
reachable from the test containers; host managed identity is not forwarded.

## CI tiers

Existing fast API/web/security/deployment gates remain intact. The separate
`cdc-reliability.yml` runs local services weekly or by dispatch, with optional
disposable outages and additional sources. Cloud execution is dispatch-only,
requires `CDC_RELIABILITY_CLOUD_CONFIG`, and reports missing configuration as
unexecuted. It never turns a skipped cloud test into a pass. Reports and failure
logs upload on both success and failure. Existing source CDC and browser gates
remain in place.

### Remaining work

Real BigQuery, Redshift and Synapse verification requires dedicated configured
resources and least-privilege credentials; Oracle requires approved database and
logging infrastructure. The optional runners do not provision billable resources.
Remaining local qualification includes MariaDB/MongoDB API/browser orchestration,
additional-source replay and interrupted snapshots, non-PostgreSQL history
expiration, independent JDBC destination-only outages, HA/multi-broker failures,
arbitrary out-of-order replay, schema-change faults and long-duration operation.
Unsupported combinations remain blocked rather than being enabled for testing.
See the per-provider [production assessment](v0.3.3-compatibility-matrix.md) and
[recovery limits](v0.3.3-recovery-report.md); this scope is not blanket production
certification.
