# v0.3.4 Data Quality compatibility

| Source → Destination | Model | Status |
| --- | --- | --- |
| PostgreSQL → PostgreSQL | CURRENT_STATE base tables | Implemented; real six-rule verification |
| MySQL → MySQL | CURRENT_STATE base tables | Implemented; real six-rule verification |
| PostgreSQL → MySQL | CURRENT_STATE base tables | Six-rule execution verified; conservative schema contracts below |
| MySQL → PostgreSQL | Any | Capability-gated; reverse direction remains unverified |
| MariaDB, SQL Server, Oracle, MongoDB | Any | Unsupported for Data Quality |
| ClickHouse, BigQuery, Redshift, Synapse | Any | Unsupported for Data Quality |
| S3/MinIO | Raw/history | Unsupported |
| Append-only / event log / SCD 2 or 4 | History | Unsupported even with relational adapters |
| Views / system schemas / single datasets | Any | Unsupported |

CDC provider support is separate from Data Quality eligibility. Generic adapters
never enable an unverified pair. Each side must independently authorize its role,
match the registered database, expose a base table and permit SELECT. Operators
explicitly attest comparable current-state meaning. Known insert/append/history
delivery mappings are rejected. SQL metadata cannot prove arbitrary external
dataset semantics; a checkbox does not establish a replication guarantee.

Temporal rules require matching declared semantics and known naive timezones.
MySQL TIMESTAMP is read in UTC; DATETIME needs its actual timezone. MAX does not
prove that a column captures every change. Unknown extension/domain/enum types
are inconclusive when types are compared. Charset changes, numeric narrowing,
unsigned range loss and timestamp precision/timezone loss never receive a safe
compatibility claim.

PostgreSQL → MySQL count rules compare integer measurements without converting
records. Temporal rules compare observed MAX values using common declared
semantics and explicit timezone normalization; MySQL TIMESTAMP requires UTC.
Cross-provider Schema Match currently certifies signed/unsigned integer ranges.
Known numeric narrowing or timezone-contract changes fail. Other unverified
domains (including charset/collation, special numeric values, date ranges and
JSON) return INCONCLUSIVE rather than being assumed lossless. An observed temporal
PASS is not a schema-equivalence claim. See the
[cross-provider verification](v0.3.4-data-quality-cross-provider.md).

Minimum fixtures are PostgreSQL 17.9 and MySQL 8.4; exact observed server versions
are recorded in `artifacts/data-quality/live-results.jsonl`. No other provider or
production version certification is inferred. All evidence is BEST_EFFORT.
